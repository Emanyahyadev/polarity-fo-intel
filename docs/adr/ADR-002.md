# ADR-002 — AI Employees are thin adapters over existing business agents

**Status:** Accepted
**Date:** 2026-08-07

## Context
We needed a uniform employee frame for the cycle, but the real business logic
(discovery, entity resolution, validation, classification...) already exists in
dedicated agents/services. Re-implementing it inside a new employee layer would
fork behavior and risk the two engines diverging.

## Decision
Every employee in `adapters.py` is a `_DelegatingEmployee` wrapper exposing a
framework-independent `AIEmployee` surface (mission / inputs / outputs /
authority / skills / decision / escalation / execute(state)) that **delegates**
to the existing `AgentBase` objects. Employees propose; they never re-implement
business logic; empty-window no-ops are the default success.

## Consequences
- The same employees run under **both** the LangGraph and orchestrator engines.
- Removing LangGraph later leaves the employees fully operational.
- **Positive:** one definition of intent, one set of underlying agents.
- **Negative:** contract discipline is required to keep employees honest.

Related: ADR-001, ADR-004.
