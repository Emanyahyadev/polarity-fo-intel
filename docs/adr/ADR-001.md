# ADR-001 — The operating cycle as an autonomous, scheduled loop

**Status:** Accepted
**Date:** 2026-08-07

## Context
The product dataset must stay current, but manual refresh does not scale and is
not auditable. We need a self-contained loop — one run, one trace — that the
product can invoke on a schedule without risking data integrity.

## Decision
The operating cycle is a fixed sequence of **AI Employees** (currently 14:
scheduler, engineering, discovery, entity, duplicate, enrichment, validation,
classification, governance, release, embedding, freshness, monitoring, logging;
see `graph.py::ROLE_ORDER`). Each run is invoked from `operations/operate.py`,
is idempotent, and writes a raw JSONL trace plus a canonical summary.

## Consequences
- Every run is independently auditable from the trace.
- A scheduled cycle regenerates the observable history artifacts (`notes/*`).
- **Positive:** reproducible, schedulable, self-documenting.
- **Negative:** an un-run cycle is silent (mitigated by Monitoring/Runbook).
