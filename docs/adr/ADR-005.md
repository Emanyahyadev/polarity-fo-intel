# ADR-005 — Observability as committed, generated artifacts (no public dashboards)

**Status:** Accepted
**Date:** 2026-08-07

## Context
The operating system must be auditorable by a normal reader. Third-party
dashboards die with the account and are not reviewable in the repo. Public
runtime endpoints are not yet authorized. We need observability that survives
exactly as long as the repository.

## Decision
Observability is file-and-commit based:
- `logs/operating/*.jsonl` per-run traces; `*-summary.json` canonical summaries.
- `notes/{run,build,session}_history.md` **generated** by
  `scripts/generate_history.py` from the traces + git (never hand-edited), and
  regenerated by CI after each operating cycle.
- The `HumanReviewQueue` printed by `operate.py` is the operator dashboard.
- No public monitoring endpoint in this phase.

## Consequences
- The observable trail is in git, durable and reviewable.
- **Positive:** "dashboard as commit"; survives as long as the repo.
- **Negative:** stale artifacts are only caught by a human noticing silence
  (see Monitoring §6 / Recovery §5) — the deliberate tradeoff for now.

Related: ADR-001, ADR-004, ADR-006.
