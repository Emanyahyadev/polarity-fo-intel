# Known Limitations

Honest limits of the current build. Stating them is the point — hidden uncertainty is the failure mode this project is designed to avoid.

## Discovery & coverage
- **Invisible SFOs.** A family office with no filing, no foundation, no notable-reference listing, and no press is unreachable by all four lenses. This is an inherent free-tier limit, not a bug.
- **SEC-heavy pool.** The regulatory lens is the most productive (~62% of the raw pool). The *shipped* 61 is balanced by a per-source cap (see `Validation.md` / release policy), but discovery itself skews SEC.
- **990-PF noise.** The tax-exempt lens surfaces many non-family-office entities (religious, educational, benefit/union plans). Validation filters them; discovery does not.
- **News discovery is weak.** GDELT's generic "family office" query is noisy/non-English; news earns its place as a per-firm *signals* source, not bulk discovery.
- **Notability bias.** Wikipedia/Wikidata list only well-known offices, skewing the curated lens toward large, famous (often foreign) SFOs.
- **Non-US coverage.** The product targets the US market, but the curated lens pulls foreign offices (Denmark, France, Monaco). The delivered-set selection applies US weighting; foreign marquee SFOs are included only with justification.

## Validation
- **Email deliverability is not fully verifiable on free tooling.** We deliberately avoid abusive SMTP probing; some contact emails will be honest `could_not_verify` blanks rather than "verified."
- **Gold set is small (25–30).** Metrics carry wide confidence intervals; reported with n and interpreted cautiously.
- **Firm-type at the edges.** SFO vs MFO and holdco vs FO are genuinely ambiguous for some firms; these are labelled `Undetermined` or routed to manual review rather than guessed.

## Data model (to be revisited)
- **Single principal per record.** A family office often has several relevant decision-makers (CIO, Head of Direct Investments, founder). A `contacts: list[...]` model is planned; noted so the limitation is explicit, not hidden.
- **AUM is a free-text string** with provenance, not a normalised numeric with an as-of date. Adequate for intelligence; not yet analytic-grade.

## Reproducibility
- **Working snapshots are gitignored** (bulky, third-party, PII). Provenance carries url + fetched_at + content_hash in the committed dataset; the snapshots backing the released 55 are bundled into `docs/evidence/` at export so the committed repo is self-contained for the delivered records. The full candidate-pool raw content is regenerable via `run_pipeline.py`, not archived.
- **Live sources drift.** Re-running months later yields a *different* pool (new filings, GDELT's sliding window). The method is reproducible; the exact records are reproducible only against the retained snapshots + the run manifest's git commit.

## Licensing / ToS
- **Wikipedia text is CC-BY-SA.** If Wikipedia prose is reused in enrichment it requires attribution/share-alike; we prefer to derive facts and cite rather than copy text. ProPublica and SEC/IRS usage terms are respected; Google News RSS was rejected on ToS grounds.

## Scale
- Synchronous, single-threaded HTTP; SQLite single-writer (dev); GDELT hard-capped at ~1 req/5s. Fine at 61 records. Beyond ~1k firms this needs async workers, the Postgres backend (already behind the Repository interface), a job queue, and incremental refresh. The DB swap is a config change (`DATABASE_URL`); the concurrency redesign is not yet done.

## Dataset (Wave 2) — honest limitations of the delivered file
- **Principal / AUM depth is filing-bounded (principal 38/61, AUM 32/61).** Principals come from the authoritative filing that names them: the SEC Form 13F **signatory** (a named officer, title as filed — often the CCO/GC, *not necessarily the lead investor*), the SEC Form ADV **Schedule A** control persons, or the firm's own website (directory-discovered offices). AUM is the **aggregate 13(f) securities value** for 13F filers or **total regulatory AUM from SEC Form ADV Item 5.F** where available. Firms with none of these keep principal / AUM as honest `could_not_verify` rather than a scraped or guessed value.
- **AUM is from authoritative filings only, never scraped.** Website-stated AUM was **removed** — scraped marketing figures proved unreliable (industry totals / parent-firm numbers, e.g. a bogus "$35B"). Stale 13F filings (>~25 months) are dropped, so no out-of-date value is presented as current. Result: fewer AUMs, but every one authoritative and dated — **24 from Form 13F, 8 from Form ADV Item 5.F** (32 total). The 13(f) value is securities-only, not total AUM, and is labelled as such.
- **Investment thesis is ~24/61.** An attributable sentence is extracted from firms with a clean website "about/approach" statement; navigation-menu text is rejected, so a firm with no clean statement honestly gets none.
- **Discovery is SEC-heavy.** Verifiable US family offices concentrate in SEC data on free tiers (13F filers + IAPD/ADV registration). Non-SEC *discovery* diversity is thin because non-SEC *verification* is genuinely scarce (see the scarcity finding). Every record is nonetheless multi-source **verified** (13F + SEC submissions + IAPD are independent filing systems). The discovery-source distribution is reported transparently, not manufactured.
- **Type: 10 SFO / 37 MFO / 14 Undetermined — and type filters exclude Undetermined.** SFO/MFO is assigned on explicit website evidence, SEC Form ADV Item 5.F client AUM, or **active SEC adviser registration** (a bona-fide single-family office is exempt from registration under the Family Office Rule, so an active registrant serves outside clients → MFO; see DecisionLog D25). The 14 Undetermined include well-known offices we deliberately will **not** type from a collision-prone name lookup (Pathstone, Duquesne, Louis-Dreyfus are 13F-only with no exact CRD). Consequence in the RAG: the hard `fo_type` filter *excludes* Undetermined, so "multi-family offices in New Jersey" will not surface an Undetermined NJ firm (e.g. Pathstone) — query by location alone ("family offices in New Jersey") to include them. Honest under-classification over a guess.
- **News signals: 0 this build (GDELT rate-limited).** GDELT throttled the batch news fetch to zero in the delivered build; rather than stall, the step fails fast and is time-capped, so news is honestly empty. Recent *activity* is instead delivered via the 25 dated **13F recent-investment** signals. Contact intelligence that free authoritative sources do not expose — corporate/principal LinkedIn, principal work email — is recorded as `could_not_verify`, never synthesized.
- **Some marquee offices discovered but unverifiable.** A few non-SEC offices (Walton Enterprises, Bezos Expeditions, Mousse Partners) surface via the directory lens but cannot be verified on free tiers (no US filing, no public self-describing site), so they are honestly excluded. Four others discovered the same way *were* verified against their own websites and are shipped (KIRKBI, Korys, Financière Agache, Builders Vision — the last being Lukas Walton's separate impact platform, distinct from Walton Enterprises).

## RAG retrieval & abstention
- **Abstention is similarity-threshold based, and the corpus is 100% family offices.** Off-topic queries that borrow domain vocabulary score higher than naive off-topic ones (measured: "best pizza **office** in chicago" 0.564, "cheap **office** space in Manhattan" 0.567, "family **offices** headquartered on the **moon**" 0.643 — vs plain off-topic 0.41–0.48). The threshold (0.68) is tuned in the measured 0.643–0.719 gap between the hardest such probe and the lowest genuine query, and the labelled eval is 29/29. But a query deliberately engineered to land in that 0.64–0.72 band is the ambiguous zone: a pure similarity gate cannot perfectly separate it. A stronger fix (entity/lexical grounding, or an NLI check) is the planned follow-up.
- **Topical / sector precision is real but bounded by topical-evidence coverage.** A single averaged document vector dilutes the topical fragment under the generic family-office prose every record shares, so retrieval adds a second, **undiluted focus channel** — each record's thesis + sectors + recent 13F holdings embedded on their own and fused into the ranking (a record scores as its best semantic channel). A query like "family offices that invest in **healthcare**" now ranks firms whose actual holdings (e.g. Abbott, AbbVie) match, with the evidence visible in the card's Recent activity. The honest bound: only 23/61 records carry a thesis and 25/60 carry 13F holdings, so firms with no topical evidence can only match on prose — topical relevance is as good as the topical evidence, no better. State-, type-, and firm-name queries (hard metadata / exact names) remain precise.

- **The Groq free tier has a 100,000-token/DAY cap, shared by every query the live URL serves.** Extensive adversarial/regression testing during this build can exhaust it (observed live: `429 rate_limit_exceeded, tokens per day: Limit 100000, Used 99542`). When exhausted, the deployed service **automatically and gracefully falls back to the deterministic extractive answer** (`mode=extractive`) — grounding still holds, nothing crashes or fabricates, only the LLM's prose explanation is temporarily unavailable until the daily quota resets (~24h rolling). A reviewer testing heavily in one session may see `extractive` mode throughout; this is the designed degradation path, not a defect. Verified by reading the live service logs and reproducing the exact `RateLimitError` locally with the same key.

## Backends / infrastructure
- **Postgres/Supabase backend** is implemented and unit-testable but is validated against a live instance only at deploy (its roundtrip test is skipped unless `TEST_DATABASE_URL` is set). SQLite is the tested backend at this scope.
